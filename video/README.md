# AAM year-wrap videos

A personalised end-of-year video for each student, built from their two
**All About Me** surveys (AAM1 at the start of the year, AAM2 at the end).

```
schools/{id}/surveys/AAM1-*, AAM2-*  ──►  buildStoryline()  ──►  storyline JSON  ──►  Remotion  ──►  MP4
          (+ responses/{studentId})        src/storyline/        (reviewable,         src/remotion/
                                                                  editable)
```

- **Segments**: `prep` (AAM1-prep / AAM2-prep) and `mid` (AAM1-mid / AAM2-mid).
  Each segment has its own theme: colours, font and music.
- **Storyline**: plain JSON listing the scenes. It's the only input the
  renderer needs, so an edited storyline re-renders without re-reading the
  surveys.
- **Missing answers** degrade step by step. Both rounds give an "evolved" or
  "stayed" scene, one round gives a single statement, and neither gives a
  generic line (dream) or drops the scene. Each degradation is listed in
  `storyline.warnings`.

## Commands

```bash
npm install
npm test                    # storyline engine tests (node --test)
npm run studio              # Remotion Studio: live preview with the sample props
npm run render:samples      # renders fixtures/sample-students.mjs → out/*.mp4
npm run music               # regenerates public/music/*.mp3 (numpy + ffmpeg)
npm start                   # the render service (needs Google credentials, see below)
```

In the cloud sandbox, point Remotion at the preinstalled Chromium:
`REMOTION_BROWSER=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`.

Rendering needs an emoji font on the machine (`fonts-noto-color-emoji` on
Debian/Ubuntu). Without one, the answer emojis render as boxes.

## Files

| Path | What |
|---|---|
| `src/storyline/questions.mjs` | Which AAM question plays which role, matched by id and then by text |
| `src/storyline/copy.mjs` | Every line the video says, with per-student variants |
| `src/storyline/buildStoryline.mjs` | Answers → scenes, with fallbacks and warnings |
| `src/remotion/` | The template: theme per segment, 10 scene types |
| `fixtures/aam-surveys.json` | Real AAM question/option definitions (English only, no student data) |
| `fixtures/sample-students.mjs` | Fictional students used for tests and sample renders |
| `public/music/` | Original background tracks generated by `scripts/make-music.py`, no licence needed |
| `server/` | The render service: roster/answers reads, saved edits, render queue, uploads |

## The dashboard page

**Year-Wrap Videos** (`/year-wrap`, ops admins only; `src/views/YearWrap.vue`):

1. Pick a school. Classes with Preparatory or Middle students are listed,
   with how many answered AAM1 or AAM2.
2. Pick a class. Each student shows AAM1 and AAM2 status, whether the story
   is complete or how many gaps were filled, and their video status.
3. **Review** opens a live preview (the real template, played in the
   browser) beside every line of the story as editable text. You can also
   remove optional scenes. **Save** keeps the edit. **Reset to automatic**
   drops it.
4. **Render** queues the selected students, or the whole class. Status
   updates live. Rendered videos can be watched in place or downloaded as
   a ZIP per class.

The storyline is built in the browser, so the service renders exactly what
was reviewed.

A student's segment comes from the AAM survey they answered (`-prep` or
`-mid`). If they answered neither, it comes from their grade: 3–5 is
Preparatory and 6–8 is Middle. The academic year is taken from the AAM1
survey dates, and ops can change it.

## Share links (recommended: no rendering)

**Create links** gives each student a private link such as
`https://clarified-1501.web.app/w/k3J9…` (the id is 128 random bits).
Opening it plays the video **in the parent's browser**, using the same
template and music, from `wrap.html` / `src/wrap/main.jsx`. That page is a
separate, light entry with no dashboard code and no login.

- Nothing is rendered or stored except the storyline, about 5 KB per child,
  in `year_wrap_links/{linkId}`.
- Re-publishing (or saving an edit in Review) keeps the same link and
  updates what parents see within a minute.
- **Revoke** deletes the link. Creating a link again issues a new address.
- **Download links (CSV)** gives Student, Class, Link and a ready-to-send
  WhatsApp message.
- The parent's page only receives what the video shows (names, class,
  school, answers), never ids or review notes.
- Hosting routes `/w/**` to `wrap.html` (`firebase.json`). The page reads
  the storyline from the service's public `GET /w/:linkId`, so the
  service's `ALLOWED_ORIGINS` must include the Hosting domain.

MP4 rendering (below) is still there for anyone who needs a file.

## Render service API

All routes are `POST` with a JSON body. Each call needs a Firebase ID token
from an ops admin, sent as `Authorization: Bearer …`. The allowlist mirrors
`src/config/opsAdmins.js`.

| Route | Body | Returns |
|---|---|---|
| `/roster` | `{schoolId}` | school, AAM survey definitions, who responded, light roster |
| `/answers` | `{schoolId, studentIds ≤200}` | AAM responses, saved edits and video state |
| `/status` | `{schoolId, studentIds?}` | video state (polled every 4 s while rendering) |
| `/save` | `{schoolId, studentId, storyline \| null}` | saves an edit (`null` resets it) |
| `/render` | `{schoolId, academicYear, items: [{studentId, storyline}]}` | queues renders |
| `/cancel` | `{schoolId}` | drops this school's queued renders |
| `/publish` | `{schoolId, items: [{studentId, storyline}]}` | creates or updates share links, returns `{links: {studentId: linkId}}` |
| `/unpublish` | `{schoolId, studentIds}` | revokes those links |
| `GET /w/:linkId` | — | **public, no sign-in**: the storyline a link plays |

State lives in `schools/{schoolId}/year_wrap_videos/{studentId}` and moves
through `queued → rendering (progress) → done (videoUrl, thumbUrl) | failed (error)`.

Videos are stored at `year_wrap/{schoolId}/{academicYear}/{studentId}.mp4`
(plus a `.jpg` thumbnail) in the default bucket, behind a Firebase download
token.

The queue is held in memory and renders one video at a time, about 40 s for
a 1-minute video on 4 vCPU. Output is 720×1280 (`OUTPUT` in
`server/render.mjs`), about 5 MB per video. If the instance restarts, its queued students
stay "queued". After 30 minutes the page shows them as "Stuck — render
again".

## Deploying

The service runs on Cloud Run, because Remotion needs Chromium.

```bash
gcloud run deploy year-wrap --source video --project clarified-1501 --region asia-south1 \
  --memory 8Gi --cpu 4 --no-cpu-throttling --timeout 3600 --concurrency 20 \
  --min-instances 0 --max-instances 1 --allow-unauthenticated \
  --set-env-vars ALLOWED_ORIGINS=https://<dashboard-domain>
```

- `--allow-unauthenticated` only opens the service at the Cloud Run IAM
  level. Every route still checks the Firebase ID token and the ops-admin
  allowlist itself, because the browser can't send Google IAM credentials.
- `--no-cpu-throttling` lets renders keep running after the `/render`
  response has gone back.
- `--max-instances 1` keeps the queue and Cancel on one instance.
- An idle instance can still be stopped. The page's status polling keeps it
  alive, so keep the page open during a big batch, or set `--min-instances 1`
  for the season.
- The runtime service account needs Firestore read/write
  (`roles/datastore.user`) and Storage object write
  (`roles/storage.objectAdmin`) on the default bucket.

Then build the dashboard with the service URL, e.g. in `.env.production`:

```
VITE_YEAR_WRAP_URL=https://year-wrap-xxxxx-el.a.run.app
```

To use **Download ZIP**, the browser has to fetch the videos, so the bucket
needs CORS for the dashboard origin. `gsutil cors set` **replaces** the
bucket's whole CORS config, so first check what's there
(`gsutil cors get gs://clarified-1501.appspot.com`) and add a `GET` rule for
the dashboard origin to it. Watching a video and opening it directly work
without CORS.
